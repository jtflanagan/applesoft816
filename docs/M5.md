# M5: applesoft816 on the machine

The system file, the shell and the compiler run live in KEGS (and next on
the real IIgs).  Scope and decisions: `DESIGN.md`, `INTERP.md`.

## Pieces

| File | What |
|---|---|
| `AS816.SYSTEM` (`sys/`) | the ProDOS 8 system file: checks for a IIgs, gets banks, loads the three images, sets up bank 0, calls the shell |
| `AS816.VM` (`vm/vm.bin`) | the VM and fp816, one bank image |
| `AS816.SH` (`cc/sh.bin`) | the shell (llvm-mos C): editor, BASIC.SYSTEM's commands; code bank + data bank |
| `AS816.CC` (`cc/cc.bin`) | the compiler (llvm-mos C), code bank + data bank; called by the shell (`cc/cccall.c`) |

## Memory

Nine whole banks from the Memory Manager (`NewHandle`, locked, fixed, one
bank, not special memory) under an ID from `GetNewID($1000)`:
`MMStartUp` answers `idErr` under ProDOS 8 alone, there being no
application for it to name.  The VM's, the string heap's, the shell's code
and data, the compiler's code and data, the program text's, the transfer
bank (CHAIN's variables, STORE/RESTORE's file, a SYS file on its way in)
and the stage bank (the variables' table, for STORE and CHAIN).  Given
back (`DisposeAll`, `DeleteID`) at `BYE` and before a SYS file runs.

The compiler is a separate image because one code bank no longer held
both.  The shell calls it warm (crt0: X's low byte `$5A` keeps `.data` and
`.bss`) with a request in its parameter block (`cc/main_cc.c`): compile,
a direct line, adopt a variable, the variable tables.

Bank 0 (`sys/res.inc`, `cc/res.h`): everything below `$9600` is the
program's (HIMEM `$9600`, where BASIC.SYSTEM's HIMEM is).  Above it:

| Address | What |
|---|---|
| `$9600` | the VM's direct page (fp816's too) |
| `$9700` | the VM's stubs (COUT, romcall), copied from its image |
| `$9780` | JSL: an MLI call (command `$9800`, parameters `$9880`, error `$9801`) |
| `$97C0` | JSL: a ROM call in emulation mode (`RES_A/X/Y/P`, target `RES_TGT`) |
| `$9900` | a pathname |
| `$9A00` | the way out (`sys.s` segment EXIT): the shell's call, BYE (vector back, banks back, QUIT), the `-` launcher's bytes, the Ctrl-Reset stub |
| `$9C00` | OPEN's 1K buffer |
| `$A000` | the 2K transfer buffer |
| `$A800` | five 1K buffers for open text files |

The shell's C keeps its imaginary registers in `$00-$1F`; around every call
out (ROM, MLI, VM) the glue swaps them with the machine's own (saved by crt0
on entry), so the program and the ROM see their page zero.

## The shell

BASIC.SYSTEM's commands first, on the line as typed: `RUN name` / `-name`,
`LOAD name`, `SAVE name`, `COMPILE name` (timed, not run), `CAT`/`CATALOG
[dir]`, `BYE`.  Then AppleSoft's, through the tokenizer (`compiler/parse.c`,
PARSE.INPUT.LINE ported step for step; `gsrun/parsetest` checks it against
the ROM's own routine on every corpus line and `tests/parse_cases.txt`):

- a numbered line goes into the program (FNDLIN, a move, FIX.LINKS);
- `LIST [a][-,b]` as the GS ROM lists (a space, the number, ` WORD ` per
  token, a new line at column 5 past 33 / 73);
- `NEW`; `RUN` (compiled once, run again without compiling);
- anything else is a **direct line**: compiled against the program's
  tables into the top of the VM bank (`$F400`: code, constants, strings;
  its new variables from the top down, strings among the collector's roots)
  and run by `vm_direct` with the program's state as it stands - variables,
  FOR/GOSUB frames, DATA, strings - or cleared if the program is new or was
  edited (AppleSoft forgets its variables then).  `RUN n`, `GOTO n`,
  `CONT` (after END, STOP, Ctrl-C; not after CLEAR/RUN/edits, as
  AppleSoft) all work from there.  INPUT, GET, DEF: `?ILLEGAL DIRECT`.
  New arrays in a direct line: `?OUT OF MEMORY` for now.

**CHR$(4) commands** from a running program (or a direct line): the VM's
OUTDO watches for a Ctrl-D first on a line, gathers up to the return
without printing, and calls the shell (`cmd_entry`, page zero swapped back
to C's).  BASIC.SYSTEM's commands (`cc/dos.c`), checked against
BASIC.SYSTEM 2.4.3 in KEGS screen for screen (`tests/dos/compare.sh`):
CATALOG/CAT in both widths, PREFIX, CREATE/DELETE/RENAME/LOCK/UNLOCK/
VERIFY, BLOAD/BRUN/BSAVE, the text files (OPEN, READ, WRITE, APPEND,
POSITION, CLOSE, FLUSH; INPUT and GET read through the VM's callbacks),
EXEC, RUN/LOAD/SAVE/CHAIN, PR#/IN#, FRE, BYE, and:

- `STORE name` / `RESTORE name` (`cc/store.c`): the variables in
  BASIC.SYSTEM's own VAR format (its tables as AppleSoft lays them out,
  strings below HIMEM `$9600`), so a VAR file goes either way between the
  two.  RESTORE clears the variables (not the stacks or DATA) first.
- `-name` on a SYS file: the file goes to the transfer bank, the shell
  leaves, and the loader copies a launcher to `$1F00` that moves the file to
  `$2000`, gives the banks back, resets ProDOS 8's bitmap, puts the full
  path at `$0280` and jumps to it in emulation mode.

**LIST, NEW, DEL** in a program or a compound direct line: the VM calls
the shell (VM_CBREQ 4, 5, 6).  LIST goes on after the listing, and lists
into WRITE's file when one is on (how a program is turned into an EXEC
file).  NEW and DEL stop the program at the prompt, as in AppleSoft
(SCRTCH; FIX.LINKS then RESTART).  A DEL that finds no lines in its range
goes on.

## Machine language

`CALL`, `PEEK`, `POKE` work on bank 0, where a program's machine code lives.
`USR(x)` copies FAC (`$9D-$AC`) into page zero, calls `$000A`, and copies it
back.  `&` copies the statement's text, token first, into the input buffer
with a stub (`JSR CHRGOT`, `JMP $3F5`), puts the ROM's CHRGET at `$B1`, and
points TXTPTR after the token.  When the routine returns, TXTPTR must be at
the end of the statement, or it is `?SYNTAX ERROR` (as NEWSTT).  The GS ROM's AppleSoft sends
SHLOAD, RECALL, STORE, SAVE and LOAD in a program to `$3F5` as well, and so
do we.  A routine that parses numbers or constants with the ROM works.  One
that reaches AppleSoft's variables (PTRGET, FRMEVL on a name) finds the
ROM's tables, not ours.

## Leaving, and Ctrl-Reset

The loader at `$2000` is the program's memory once the shell runs (HGR alone
clears `$2000-$3FFF`), so everything after the shell is resident at
`$9A00`.  BYE puts the reset vector back as found and gives every bank back
(`DisposeAll`, `DeleteID`) before ProDOS 8's QUIT.  That matters: GS/OS
stays resident and live under a ProDOS 8 program launched from the Finder
(zeroing banks `$02-$7F` from BASIC.SYSTEM crashed in GS/OS's code in bank
`$05` before BYE), and BYE resumes it rather than rebooting it.

Ctrl-Reset goes through `$3F2` to the resident stub, back into the shell
warm, as BASIC.SYSTEM's does (`tests/dos/reset1.txt`, screen for screen):

- The program stays.
- The variables go (as CLEAR), and CONT with them.
- READ/WRITE/EXEC end; the files stay open (DELETE says FILE BUSY).
- The prompt starts at column 0 of the cursor's line, with no CR.
- A reset inside the compiler forces a recompile.

Ctrl-Command-Reset is a reboot, as ever.

## Compiling on demand

RUN compiles the program in memory and keeps the bytecode in the VM bank
until the program changes (an edit, LOAD, NEW, CHAIN, a reset inside the
compiler).  Nothing compiled is written to disk *(user, 2026-10-13)*: the
`AS816.CACHE/NAME` file of the first M5 build is gone.

## Timing the compile

The GS video counter (`$C02E`, the vertical count over two: 131 values a
frame, 7867 a second), read by the compiler's `poll` at every statement -
well under a frame apart.  The firmware's tick does not count under ProDOS
8: VBL interrupts get switched off again after `IntSource(vblEnable)` (by
the MLI or the ROM's keyboard code), and enabling interrupts outright hung
the machine.

## Results (KEGS, ROM 3, 2.8 MHz)

| Program | Lines | Bytecode | Compile |
|---|---|---|---|
| BM1 | 5 | 68 | 0.03 s |
| BM7 | 13 | 215 | 0.08 s |
| Lemonade | 381 | 10430 | 4.46 s |

Compile cost on emu816 (`gsrun --cc`, `GSRUN_CCPROF` + `tools/ccprof.py`):
Lemonade went 39.3M -> 14.0M cycles with the hashed constant pool, bulk
platform reads/writes and byte-sized scanning, then to 10.6M with one pass
(2026-10-13, docs/SPEED.md): a counting scan sizes the fixed regions, the
code is written as it is compiled, constants and string literals live in
the code where first used, jumps go through a line table.  Then lazy: RUN
only scans and lays out (Lemonade: ~1.4M cycles, 0.5 s at 2.8 MHz); a jump
to a line with no code yet asks the shell (VM request 7) for it and the 15
lines after it.  COMPILE still compiles everything (9.9M cycles).

## Testing live

`tools/mkdisk.sh build/as816.po` makes the boot disk (ProDOS 2.4.3 and its
boot blocks from AppleWin's disk, ours, Lemonade, BM1-8);
`tools/kegs.sh start build/as816.po` boots it in KEGS on Xvfb `:99`;
`kegs.sh type`, `key`, `shot` drive and look.
