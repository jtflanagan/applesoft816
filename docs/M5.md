# M5: applesoft816 on the machine

The system file, the shell, the bytecode cache, run live in KEGS (and next on
the real IIgs).  Scope and decisions: `DESIGN.md`, `INTERP.md`.

## Pieces

| File | What |
|---|---|
| `AS816.SYSTEM` (`sys/`) | the ProDOS 8 system file: checks for a IIgs, gets banks, loads the two images, sets up bank 0, calls the shell |
| `AS816.VM` (`vm/vm.bin`) | the VM and fp816, one bank image |
| `AS816.CC` (`cc/cc.bin`) | the shell and the compiler (llvm-mos C), code bank + data bank |
| `AS816.CACHE/NAME` | the compiled program, beside the source |

## Memory

Five whole banks from the Memory Manager (`NewHandle`, locked, fixed, one
bank, not special memory) under an ID from `GetNewID($1000)`:
`MMStartUp` answers `idErr` under ProDOS 8 alone, there being no
application for it to name.  The VM's, the string heap's, the shell's code
and data, the program text's.  Given back (`DisposeAll`, `DeleteID`) at
`BYE`.

Bank 0 (`sys/res.inc`, `cc/res.h`): everything below `$9600` is the
program's (HIMEM `$9600`, where BASIC.SYSTEM's HIMEM is).  Above it:

| Address | What |
|---|---|
| `$9600` | the VM's direct page (fp816's too) |
| `$9700` | the VM's stubs (COUT, romcall), copied from its image |
| `$9780` | JSL: an MLI call (command `$9800`, parameters `$9880`, error `$9801`) |
| `$97C0` | JSL: a ROM call in emulation mode (`RES_A/X/Y/P`, target `RES_TGT`) |
| `$9900` | a pathname |
| `$9C00` | OPEN's 1K buffer |
| `$A000` | the 4K transfer buffer |

The shell's C keeps its imaginary registers in `$00-$1F`; around every call
out (ROM, MLI, VM) the glue swaps them with the machine's own (saved by crt0
on entry), so the program and the ROM see their page zero.

## The shell

`RUN name` / `-name`, `COMPILE name` (timed, not run), `CAT`/`CATALOG
[dir]`, `BYE`.  Next: immediate statements, the line editor, `LIST`,
`NEW`, `LOAD`/`SAVE`, `CHR$(4)` commands from programs.

## The bytecode cache

`DIR/AS816.CACHE/NAME` for `DIR/NAME` (a ProDOS name leaves no room for a
suffix).  Header: `A816`, `C`, version, the VM image's hash (the bytecode
names its handlers by address), the source's length and hash, where the
image starts, its length, then the VM bank from `prog_start` to the stacks.
A RUN loads the source (it is the program in memory either way), hashes
it, and takes the cache when everything matches; otherwise it compiles and
writes the cache (quietly not, on a write-protected disk).

## Timing the compile

The GS video counter (`$C02E`, the vertical count over two: 131 values a
frame, 7867 a second), read by the compiler's `poll` at every statement -
well under a frame apart.  The firmware's tick does not count under ProDOS
8: VBL interrupts get switched off again after `IntSource(vblEnable)` (by
the MLI or the ROM's keyboard code), and enabling interrupts outright hung
the machine.

## Results (KEGS, ROM 3, 2.8 MHz)

| Program | Lines | Bytecode | Compile | Cached |
|---|---|---|---|---|
| BM1 | 5 | 68 | 0.03 s | |
| BM7 | 13 | 215 | 0.08 s | |
| Lemonade | 381 | 10430 | 4.46 s | yes, and it runs |

Compile cost on emu816 (`gsrun --cc`, `GSRUN_CCPROF` + `tools/ccprof.py`):
Lemonade went 39.3M -> 14.0M cycles with the hashed constant pool, pass 2
replaying pass 1's FIN results, bulk platform reads/writes and byte-sized
scanning.  Left on the table: one pass instead of two (pass 2 re-parses
everything to place the constants and variables after the code), and a
fast path for FIN on small integers.

## Testing live

`tools/mkdisk.sh build/as816.po` makes the boot disk (ProDOS 2.4.3 and its
boot blocks from AppleWin's disk, ours, Lemonade, BM1-8);
`tools/kegs.sh start build/as816.po` boots it in KEGS on Xvfb `:99`;
`kegs.sh type`, `key`, `shot` drive and look.
